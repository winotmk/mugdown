# 界面语言配置

外观设置 → 界面语言，可立即切换简体中文或 English。两端共用同一套 JSON 语言包，语言设置默认随程序保存在 Windows 的 `settings.json` 或 macOS 的 `mugdown.settings.json` 中，也可切换到系统用户目录。调色板底部使用相对路径或环境目录别名显示保存位置。

## 添加语言

1. 复制 `src/i18n/locales/en-US.json`，以语言代码命名，例如 `ja-JP.json`。
2. 把顶层 `name` 改为该语言的本名，例如 `日本語`。这个名称显示在语言选择器里。
3. 只翻译 `messages` 的值，左侧键保持原样。键使用稳定的中文源短语，与 gettext 的源消息类似。
4. 保留 `{0}`、`{1}` 等占位符，以及必要的 Markdown 标记与换行符。JSON 中换行写为 `\n`。
5. 运行 `npm test` 检查所有语言包键和占位符是否一致，然后重新构建。新语言自动进入下拉框，不需要修改 TypeScript 注册表。

简化示例（完整语言包请复制现有文件）：

```json
{
  "name": "日本語",
  "messages": {
    "文件": "ファイル",
    "编辑": "編集",
    "关闭 {0}": "{0} を閉じる"
  }
}
```

界面控件、菜单、选区格式栏、段落菜单、提示和应用错误信息使用这些配置。文档内容、已有文件名、CSS、代码语言名称不会被自动翻译。系统文件对话框的系统按钮随操作系统语言显示。

## 开发约定

新文案使用 `t("源短语")`；带动态值使用 `t("关闭 {0}", {0: filename})`，同时更新各语言包。缺少翻译时回退到中文，再回退到源短语。未知语言代码安全回退到简体中文。

语言文件在构建时打包进应用，不额外引入国际化运行库。发布版不能通过在程序旁放置 JSON 临时增添语言，修改语言包后需要重新构建。
