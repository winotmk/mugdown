# mugdown 范围与架构

2026-10-21 · 从 Winotypo v0.8.0 的编辑器拆分。

mugdown 直接编辑用户选择的 Markdown 文件。没有资料库、标签与分类管理、博客属性、封面、Git、SSH、OSS、登录或左右边栏。新建文档为空白正文，不添加写作日期或 Front Matter。

YAML/TOML Front Matter 是 Markdown 生态常见的元数据扩展，不属于 CommonMark 正文语法，也并非 Hugo 独有。旧文件中的 Front Matter 保留原始文本、注释与未知字段；可在 MD 模式修改。可视化模式只排版正文，不根据头部生成标题、日期、作者、标签或封面。头部的保留是文件兼容能力。

## 界面与交互

- 顶部为文件、编辑、窗口菜单，底部为保存状态、字数和编码。查找替换位于编辑菜单。
- 格式工具条默认隐藏，顶部中央用纯图标拉手、点阵和向下箭头提示入口。悬停时向下展开，拉手变为图钉和上箭头，移开自动收起。点击拉手或工具栏任一空白区域固定；固定后拉手向上消失，只保留末端图钉解锁。悬停覆盖正文上方留白，不推动正文；固定时仅为工具栏预留 43 像素，不保留拉手空位。键盘聚焦也能展开，未固定时按 Esc 收起；减少动态效果设置会关闭动画。
- 块按钮组宽 40 像素，距正文 6 像素，正文最小左右留白 60 像素，窄窗口的标题、段落、列表和引用均有足够空间显示块操作。
- 每个窗口只有一个文档时，整个 tab 栏隐藏；两个及以上文档时显示。
- tab 可拖动排序，拖出当前窗口创建独立编辑器；拖到另一个 mugdown 窗口任意位置合并。只有一个文档时，可拖动标题栏的文件名合并；目标窗口只有一个文档时也可接收。窗口菜单提供同等操作。
- 抓住标题栏空白处拖动整个窗口，同样可以在另一个窗口任意位置松手合并；单文档仍保持隐藏 tab。目标窗口显示覆盖全窗的蓝色接收区域，来源窗口显示松手合并提示。正文、底部和标题栏全部接受合并；拖到桌面只移动原窗口，Esc 取消。
- 整窗合并先提交来源编辑器尚未提交的文字，再原子移动此窗口全部文档，保持顺序、活动文档、未保存内容和共享撤销记录。目标关闭时保留来源窗口及文档。
- 可视化编辑保留段落类型菜单、块拖动和选区格式浮动栏。只保留可视化与完整 MD 源码两种模式。
- 支持原生打开/另存为、启动参数与文件关联打开、拖入 Markdown 文件、Ctrl/Cmd 快捷键、查找替换。
- 粘贴图片时，新文档先选择保存位置。`notes.md` 的图片写入旁边的 `notes/` 文件夹，名称使用随机 ID 避免覆盖；Markdown 使用相对路径。
- 另存为会复制正文引用的相对图片到新目录，保留旧文件和原图片。
- 保存使用同目录临时文件和原子替换。文件被其他程序改动时提示另存为或明确覆盖；关闭未保存文档时提示保存/不保存/取消。

## 技术选择

React + TypeScript；Milkdown/ProseMirror 可视化编辑，CodeMirror 源码编辑；Rust + Tauri 2 提供文件与窗口服务。Windows 使用系统 WebView2，macOS 使用系统 WKWebView；不附带 Chromium、Node、Git 或图片上传 SDK。

跨窗口文档与撤销记录由 Rust 进程持有，拆分与合并移动文档归属，不经磁盘传递未保存内容。只有活动文档创建编辑器，编辑器按需载入。未使用的 AI、公式渲染、整套代码语言包不会进入发行包；代码块保持可编辑和原样保存。

外观保留原有 UI 皮肤、字号、正文宽度和自定义 CSS。Markdown 排版包括原有三种和目录扩展的 Air/Book/Compact/Notebook；程序旁 presets 目录支持新增 CSS 后刷新。工具栏入口与正文共用编辑区域底色。Windows 默认在 exe 同目录创建 settings.json；macOS 在 .app 旁创建 mugdown.settings.json。调色板显示相对路径，并可切换到系统用户目录；切换携带当前设置，程序旁小型指针记住系统模式。新位置不存在时自动迁移旧应用配置，已有文件优先；旧配置保留。失败会提示并保持原选择。文档和图片始终位于用户选择的位置。

外观设置提供简体中文与英文切换。语言配置为独立 JSON 文件，构建时自动发现，无需维护语言注册表。翻译覆盖菜单、对话框、编辑器控件、提示和文件类型名称；文档内容与已保存的文件名保持原样。旧版设置自动补上中文和工具栏默认收起，不重置原来的皮肤、CSS 等选项。详见 [语言配置](i18n.md)。

优先交付 Windows x64 与 macOS Universal（Apple Silicon + Intel）。macOS 使用原生红黄绿窗口按钮和 Cmd 快捷键。两端都必须经过各自实机验收；Windows 验证不能替代 macOS 验收。仓库提供独立的两端构建作业，不自动发布。

参考：[CommonMark 规范](https://spec.commonmark.org/0.31.2/)、[Hugo Front Matter](https://gohugo.io/content-management/front-matter/)、[Tauri WebView 架构](https://v2.tauri.app/reference/webview-versions/)。
